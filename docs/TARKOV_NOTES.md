# Что взято из Таркова и что с этим делать дальше

Документ-«карта решений»: почему стенд ощущается именно так и куда двигаться,
когда начнёшь делать сам режим.

## Уже заложено в стенд

| Механика | Где | Статус |
|---|---|---|
| Медленное, «весомое» движение (8 studs/s шаг) | `Config.Movement` | ✅ |
| Отдельные скорости: прицел / присед / бег | `PlayerController` | ✅ |
| Отдача паттерном + пружинный возврат | `Ballistics.recoilOffset`, `Recoil` | ✅ |
| ADS с посадкой прицела и сужением FOV | `Camera`, `WeaponController` | ✅ |
| Зоны урона: голова ×2.2, конечности ×0.7 | `AimSolver` | ✅ |
| Серверный хитскан (античит-основа) | `CombatService` | ✅ |
| Наклон камеры в стрейфе | `Camera:setLean` | ✅ |
| Хотбар-слоты 1–9 | `Hud`, `WeaponController` | ✅ |
| Манекены с Humanoid для теста урона | `TestRange` | ✅ |

## Следующие шаги (в порядке полезности)

1. **Патроны по типам и запас.** Сейчас `AmmoType` показывается, но `reserve`
   бесконечен. Сделать таблицу `{ ["9x19"] = 120 }` и тратить при перезарядке.
2. **Броня и пробитие.** В статах есть `Penetration`; добавить класс брони
   (`ArmorClass 1..6`), снижать урон и ломать броню.
3. **Модульная система оружия.** Сокеты уже есть: добавить `Attachments`-обвесы
   (прицел/глушитель/рукоятка) как отдельные модели, цепляемые к сокетам.
4. **Инвентарь и лут.** Слоты хотбара уже отделены от «рюкзака» — ввести
   `InventoryService` на сервере с проверкой владения оружием.
5. **Звук.** Точки подключения: `Config.Weapons.ShotSoundId`, `Tracers`.
   Для Таркова важны шаги, дыхание, щелчок затвора.
6. **Медицина/состояния.** Кровотечение, переломы — логика уже серверная.
7. **Экстракция/рейды.** Это уже мета-игра, стенд — фундамент под неё.

## Чего избегать (типичные грабли)

* Не вешать `Humanoid.CameraOffset` вместе со скриптовой камерой — получится
  двойная отдача.
* Не делать оружие `Anchored`: `Weld` не потащит анкоренную часть.
  `WeaponHolder` снимает `Anchored` автоматически.
* Не ставить оружию `CanQuery = true` — оно начнёт ловить собственные raycast'ы.
* Не поворачивать персонажа через `Humanoid.AutoRotate` при скриптовой камере —
  будет «петля» камера ↔ персонаж. В стенде поворот делается вручную
  (`updateCharacterRotation`).
